BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The controls this agent declares are genuinely implemented — and the newest
tools were added around them rather than through them. The --allow-writes
gate, the result-size bound and the canonicalizer are all real, enforced twice
over in places, and the ABV-004 tag-neutralization fix is correctly closed.
But the three report-rendering tools accept a model-supplied output_path and
write_text to it with mkdir(parents=True), escaping the reports/ containment
the remit grants, while render_dashboard additionally reads any file on the
host through config_path. The second pattern is that every guardrail is wired
to the success path only. _ok canonicalizes; _err does not — and because
ExaAPIError carries the raw tenant response body, any HTTP 400 or above hands
unfiltered tenant bytes straight to the model, defeating the
smuggling-code-point strip on precisely the channel an attacker would choose.
The same shape recurs in the audit trail, which records the neutralizer's
inputs but never its interventions, and in find_guid_users, which returns a
clean zero when the check never ran.
